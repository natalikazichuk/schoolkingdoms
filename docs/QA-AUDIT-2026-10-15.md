## 2. Як тестували

1. **Сервер:** `cd server/app && npm install && npm test` — вбудований `node:test`.
2. **Статичний аналіз:** новий скрипт [`tools/qa/static-audit.mjs`](../tools/qa/static-audit.mjs) — `node --check` для кожного скрипта, дужки CSS, наявність локальних файлів, розбіжні `?v=N`, `lang` / `title` / `viewport`.
3. **Смоук повної версії:** новий скрипт [`tools/qa/site-smoke.mjs`](../tools/qa/site-smoke.mjs) — Chromium (Playwright) відкриває кожну сторінку, `/api/*` відповідає «гість»; ловить `pageerror` і 4xx на локальні файли.
4. **Смоук демо:** `node tools/build-demo.mjs && node tools/demo-smoke.mjs`.
5. **Ручний рев’ю коду:** `server/app/src/*` (API, правила, паролі, сесії), `server/nginx/site.conf`, `sw.js`, вибірково — екранування в `hero.html`, `admin-reports.html`, `sk-avatar.js`, `firebase-config.js`.
6. **Перевірка гіпотез запуском:** запити до API з `Origin: null` і зіпсованим cookie (див. 3.1).

> **Обмеження.** Логіку сторінок після входу (кабінет батьків, арена, адмінка) браузерний смоук не проходить — потрібна тестова база. Це окремий пункт плану (етап 3).

## 4. Що працює добре ✅

- Серверні правила доступу перенесені з Firestore акуратно, з тестами; поля книги вмінь змінює лише сервер.
- Паролі — scrypt із сіллю, `timingSafeEqual`, автоматична міграція з Firebase-хешів; сесія — HttpOnly + Secure + SameSite, у базі лише sha256 токена.
- Захист від CSRF: лише `application/json` + перевірка `Origin`.
- SQL — повністю параметризований; поля `where` перевіряються регуляркою.
- Сторінки «деградують м’яко»: немає картинки/звуку → емодзі/запасний фон, без падінь (підтверджено смоуком).
- Документація (README, `server/README.md`, `shema-adminky.md`) — детальна й актуальна.

4. nginx: для файлів з `?v=` віддавати `Cache-Control: public, max-age=31536000, immutable` (через `map $args`), `no-cache` лишити для HTML; увімкнути `gzip`/`brotli` для `.js/.css/.html/.json`.
